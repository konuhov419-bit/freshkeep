# Промпты для анализа логов FreshKeep

Подготовка: выгрузите логи (`railway logs > logs.txt` или `logs/api.log`), уберите лишнее (`tail -n 2000`). Секреты в логах уже маскируются, но перед отправкой во внешний AI проверьте выгрузку.
Сначала запустите `npm run analyze-logs -- logs/api.log --json` и передайте AI готовую сводку вместе с фрагментом логов вокруг интересных `reqId`.

## 1. Общий разбор
```
Ты SRE. Ниже JSON-логи Node.js-приложения (поля: ts, level, event, reqId, status, ms, path).
1) Сгруппируй ошибки (level=error/warn) по причине и дай количество.
2) Для каждой группы: вероятная причина, как воспроизвести, что исправить.
3) Отдельно перечисли аномалии по времени (всплески).
Отвечай таблицей, не выдумывай причины, которых нет в логах; если данных мало — так и скажи.
```

## 2. Подозрительная активность
```
Найди в логах признаки атак: много auth.login_failed с одного ip-хэша, auth.locked, сканирование адресов (много 404 на /wp-*, /.env, /admin), необычно частые запросы. Для каждого случая укажи ip-хэш, число событий, интервал времени и рекомендацию (блокировка на прокси, CAPTCHA, ничего).
```

## 3. Производительность
```
По событиям http.request построй список маршрутов с p50/p95 по полю ms (идентификаторы в пути заменяй на :id). Для маршрутов с p95 > 500 мс предложи причины (индексы БД, размер ответа, блокировки SQLite) и проверку для каждой гипотезы.
```

## 4. Расследование одного запроса
```
Вот все строки с reqId=<ID> и 20 строк до/после. Опиши, что произошло по шагам, где возникла ошибка и какой код нужно проверить (укажи файл по стеку).
```

## 5. Проблемы OAuth
```
Покажи все oauth.provider_error и связанные http.request на /api/auth/oauth/*. Определи, что сломалось: Client ID/Secret, redirect_uri, срок действия кода, недоступность провайдера. Перечисли, что проверить в консоли провайдера.
```

## Проверка на типичных ошибках
Файл `docs/samples/problem.log` содержит 8 заложенных проблем (необработанная SQLITE_BUSY, 5xx, подбор пароля, блокировки, сбой Яндекса, медленный маршрут, сканирование 404, битая строка). `npm run analyze-logs -- docs/samples/problem.log` находит все (результат: `docs/samples/problem-report.txt`); тот же файл можно отдать AI с промптом №1 и сравнить выводы.
