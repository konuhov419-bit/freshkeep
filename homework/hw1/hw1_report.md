# ДЗ 1. Сравнительный анализ и настройка AI-инструментов

## 1. Задача и требования проекта

**Задача:** разработать MVP мобильного приложения FreshKeep (учёт продуктов дома, напоминания о сроках, рецепты). Требования описаны в ДЗ 3: `technical_specification.md`.

| Требование | Значение | Влияние на выбор |
|---|---|---|
| Сложность | Средняя: мобильный клиент, REST API, БД, push-уведомления, автотесты | Нужен агент, который работает с многофайловым проектом и запускает тесты |
| Доступ к локальным файлам | Нужен: монорепозиторий, спецификация в Markdown, тесты | Предпочтительны IDE/CLI-агенты |
| Безопасность данных | Код проекта не публикуется до релиза; персональных данных в коде нет | Облачные генераторы допустимы только для прототипа |
| Бюджет | До $20 в месяц | Подходят Copilot Pro ($10), Claude Pro ($20), Aider с оплатой API |
| Процесс | ТЗ в формате Markdown → задачи → код с тестами | Важно качество кода и работа по спецификации |

## 2. Анализ инструментов

Рассмотрено 7 инструментов: **3 Cloud-агента** (Lovable, Bolt.new, Replit Agent) и **4 IDE/CLI-агента** (Cursor, GitHub Copilot, Claude Code, Aider). Полная таблица оценок, цен и обоснований — в `hw1_comparison_table.md`.

**Cloud-агенты** (Lovable, Bolt.new, Replit Agent) работают в браузере: вы описываете приложение текстом, агент создаёт проект в облаке и сразу показывает результат. Они подходят для быстрых веб-прототипов, но код живёт в облачной среде вендора, доступа к локальным файлам нет, а расход кредитов трудно предсказать. У Lovable скачать код можно только на платных планах.

**IDE/CLI-агенты** (Cursor, Copilot, Claude Code, Aider) работают с локальным репозиторием: читают файлы, правят код, запускают команды и тесты. Это основной формат для долгой разработки с git и тестами.

Различие между типами: Cloud-агент владеет всей средой (проект, запуск, хостинг), IDE-агент помогает внутри вашего редактора и репозитория, CLI-агент работает из терминала и сам выполняет команды.

## 3. Выбор инструмента

**Выбран: Claude Code** (CLI-агент).

**Ключевые факторы**
1. **Работа со всем репозиторием и спецификацией.** Агент читает ТЗ и User Stories, правит несколько файлов и сам запускает тесты, что соответствует процессу «ТЗ → код → тесты».
2. **Качество результата.** Цикл «написал код → запустил тесты → исправил» снижает число ошибок, критерии Given-When-Then из `user_stories.md` легко превращаются в тесты.
3. **Не привязан к редактору.** Работает из терминала рядом с любым IDE и CI.
4. **Бюджет.** Входит в Claude Pro ($20 в месяц), то есть укладывается в лимит.

**Как разрешена ничья с Copilot (4,25 против 4,25).** По сумме баллов инструменты равны. Для этого проекта перевесила способность Claude Code самостоятельно выполнять многошаговые задачи с запуском тестов, а у Copilot сильнее интеграция с редактором и ниже цена.

**Честная оговорка.** Автор анализа и практической части — Claude, то есть модель, на которой построен выбранный инструмент. Оценки экспертные и могут быть смещены в пользу «своего». Поэтому рядом приведена альтернатива, а проверить выводы стоит на собственном опыте.

### Альтернативы и почему не подошли

| Альтернатива | Когда лучше | Почему не выбрана |
|---|---|---|
| GitHub Copilot Pro ($10) | Бюджет минимальный, работа внутри VS Code, нужны подсказки по ходу набора | Слабее на длинных автономных задачах; при равных баллах выбран инструмент с более полным циклом «код → тесты» |
| Cursor | Хочется IDE с глубоким индексом проекта и безопасностью (SOC 2, Privacy Mode) | Структура тарифов сложнее, на тарифах выше $8 включена оплата сторонних моделей по цене API, что хуже предсказуемо для бюджета |
| Aider | Нужна максимальная приватность (локальные модели) или бесплатный инструмент | Больше ручной настройки, слабее интеграция |
| Lovable, Bolt.new | Быстрый веб-прототип интерфейса | Нет доступа к локальным файлам, код привязан к платформе, выше риск для безопасности данных, ориентированы на веб, а не на мобильное приложение |
| Replit Agent | Облачное окружение «всё в одном» | Расход кредитов зависит от сложности запроса, облачное хранение кода |

## 4. Настройка рабочего окружения

### Что выполнено в песочнице

Тестовый проект `hw1_demo/` создан в рабочей среде Claude (Linux, Node.js 22):

```
hw1_demo/
├── package.json            # "test": "node --test"
├── src/freshness.js        # функция getFreshness (FR-2.7)
└── test/freshness.test.js  # 8 тестов по критериям US-05
```

Тесты запускаются командой `npm test` без внешних зависимостей. Дополнительный MCP-сервер не потребовался: задача не требует внешних данных (при необходимости можно подключить GitHub MCP для работы с задачами и pull request).

### Что нужно выполнить на вашем компьютере

Эта часть требует вашей машины, поэтому я её не выполнял и скриншотов не выдумывал:

1. Установить Claude Code по актуальной инструкции Anthropic и войти в аккаунт (Pro или Max).
2. Открыть папку `hw1_demo/` в терминале и запустить агента.
3. Выполнить `npm test` и сделать скриншот результата.
4. Приложить скриншоты в раздел «Демонстрация работы».

## 5. Практическое применение

**Задача:** реализовать функцию определения свежести продукта по критериям FR-2.7 / US-05 из ТЗ ДЗ 3 (зелёный: более 3 дней; оранжевый: 1–3 дня; красный: сегодня или просрочено; серый: без срока) и покрыть тестами.

**Использованный промпт (суть):**

> Реализуй функцию `getFreshness(expiresAt, today)` по требованию FR-2.7: статусы green/orange/red/none и подпись на русском («12 дней», «сегодня», «просрочено 2 дн.», «без срока»). Время суток не должно влиять на результат. Напиши тесты по критериям US-05 и запусти их.

**Процесс и результаты**

| Параметр | Значение |
|---|---|
| Итераций | 2: первая версия (код + 8 тестов); вторая — упрощение формирования подписи «просрочено N дн.» |
| Результат запуска | 8 из 8 тестов пройдены, до и после рефакторинга |
| Трудности | Расчёт дней должен учитывать только календарную дату, иначе результат зависит от времени суток; русское склонение (1 день, 2 дня, 5 дней, 11 дней, 21 день) |
| Решения | Разница считается по датам в UTC-полночь; отдельная функция `pluralDays` с учётом исключений 11–14 |
| Замечание по качеству | В первой версии подпись «просрочено» строилась цепочкой `replace`; это работало, но было хрупко, поэтому код упрощён до `Math.abs(daysLeft)` |

Ключевая часть кода:

```js
const daysLeft = daysBetween(today, expires);
if (daysLeft < 0)  return { status: "red",    daysLeft, label: `просрочено ${Math.abs(daysLeft)} дн.` };
if (daysLeft === 0) return { status: "red",    daysLeft, label: "сегодня" };
if (daysLeft <= 3) return { status: "orange", daysLeft, label: pluralDays(daysLeft) };
return { status: "green", daysLeft, label: pluralDays(daysLeft) };
```

Эта часть выполнена в среде Claude, а не в вашей установке Claude Code. Для сдачи повторите задачу у себя и приложите свои скриншоты.

## 6. Выводы и рекомендации

1. **Cloud и IDE/CLI-агенты решают разные задачи.** Cloud — быстрый прототип без настройки. IDE/CLI — поддерживаемый код в вашем репозитории, с тестами и git.
2. **Для проекта FreshKeep рекомендуется связка:** Claude Code (или Copilot Pro как бюджетная альтернатива) для разработки; Lovable или Bolt.new — только для быстрого эксперимента с интерфейсом без реальных данных.
3. **Безопасность.** Для закрытого или чувствительного кода предпочтительны инструменты с локальным доступом и понятной политикой данных (Privacy Mode у Cursor) либо Aider с локальной моделью. Для проектов, подпадающих под требования к хранению данных, стоит заранее проверить, где обрабатывается код.
4. **Метод.** Спецификация в Markdown с критериями приёмки заметно упрощает работу агента: каждый критерий превращается в тест.
5. **Ограничения анализа.** Оценки экспертные; цены меняются, перед покупкой нужно сверять их на официальных страницах; Lovable не публикует цену Free на странице тарифов, а страница Cursor содержит нестандартные планы, поэтому сумма в бюджете может отличаться.
