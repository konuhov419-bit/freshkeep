# ДЗ 2. Проект и стек (Шаг 1)

## Проект

**FreshKeep** — мобильное приложение для учёта продуктов дома, контроля сроков годности и подбора рецептов из имеющихся продуктов. Это новый проект из ДЗ 3 (`project_description.md`, `technical_specification.md`). Правила написаны для работы AI-агента над его кодовой базой.

## Технологический стек

| Слой | Технология |
|---|---|
| Язык | TypeScript 5 (`strict: true`) |
| Клиент | React Native (Expo), React Navigation, TanStack Query |
| Бэкенд | Node.js 22 + NestJS, REST API (OpenAPI 3.0) |
| БД | PostgreSQL, миграции через Prisma |
| Push | Firebase Cloud Messaging |
| Тесты | Jest (клиент и сервер), встроенный `node:test` для чистых утилит |
| Качество | ESLint + Prettier, Husky (pre-commit), GitHub Actions |

## Ключевые требования к стилю, архитектуре и стандартам

1. **Типобезопасность.** Никаких `any`; строгие типы на границах (API, БД, формы).
2. **Архитектура.** Бизнес-логика — в чистых функциях без побочных эффектов (`src/domain`), I/O — в тонком слое сервисов; компоненты UI не содержат бизнес-логики.
3. **Тестируемость.** Каждая функция домена покрыта тестами по критериям Given-When-Then из `user_stories.md`.
4. **Обработка ошибок.** Единый формат ошибки API (`{ error: { code, message, field? } }`), тексты для пользователя на русском.
5. **Безопасность.** Валидация входных данных на сервере, секреты только из переменных окружения, доступ только к данным своего Household.
6. **Стандарты разработки.** Conventional Commits, небольшие pull request, обязательный линтер и тесты в CI.
