# Отчёт по ДЗ 3: проработка требований с помощью AI-агента

## 1. Что сделано

Для продуктовой идеи **FreshKeep** (мобильное приложение для учёта продуктов дома, контроля сроков годности и подбора рецептов) пройдены все шаги задания: от формулировки идеи до технического задания.

| Шаг | Результат | Файл |
|---|---|---|
| 1. Продуктовая идея | Проблема, ценность, 3 сегмента ЦА, 5 функций MVP, метрики и риски | `project_description.md` |
| 2. UI-концепции | 3 концепции (минимализм, яркая карточная, корпоративная): код, скриншоты, плюсы и минусы, оценочная таблица, выбор №2 | `ui_concepts/` |
| 3. User Story Mapping | 3 персоны, 4 пользовательских сценария, карта историй, 17 User Stories по MoSCoW | `user_stories.md` |
| 4. Критерии приёмки | Given-When-Then для всех 17 историй, позитивные и негативные случаи | `user_stories.md` |
| 5. Обработка ошибок | Счастливые пути, список ошибок по 4 категориям, UX-решения | `user_stories.md`, `technical_specification.md` |
| 6. Техническое задание | FR-1…FR-6, нефункциональные требования, ERR-1…ERR-15, модель данных, Definition of Done | `technical_specification.md` |

## 2. Роль AI-агента

- **Идея и ресёрч:** выбор идеи, формулировка проблемы и аудитории, оценка рисков.
- **UI:** по текстовым промптам сгенерирован код трёх макетов, затем сделаны скриншоты. Для сравнения использована взвешенная оценка концепций.
- **Истории и критерии:** генерация историй по этапам пути пользователя, затем приоритизация и написание критериев приёмки.
- **Ошибки:** сгенерирован список возможных ошибок, из него отобраны значимые и описаны UX-решения.
- **ТЗ:** истории преобразованы в нумерованные требования для AI-инженера. Проверка полноты проведена по чек-листу критериев оценки.

## 3. Проверка по критериям приёмки

| Критерий | Требование | Факт |
|---|---|---|
| Различные UI-концепции | ≥ 3 | 3, с разным стилем и компоновкой, выбор обоснован |
| User Stories | ≥ 5 | 17, в формате «Как…, я хочу…, чтобы…», с приоритетами |
| Acceptance Criteria | для ≥ 3 функций | для всех 17 историй, формат Given-When-Then |
| Негативные сценарии | ≥ 3 типа | 4 типа: валидация, нет данных, сеть, доступ (+ разрешения) |
| ТЗ | Структура + детальные требования | Все разделы есть, требования пронумерованы |

## 4. Выводы и ограничения

- Чёткая структура «история → критерии → требование → тест» (идентификаторы US-*, FR-*, ERR-*) упрощает передачу ТЗ AI-инженеру и проверку результата.
- Приоритизация показала: ценность продукта держится на связке «инвентарь + напоминания + рецепты», поэтому баннер с рецептом вынесен на главный экран.
- Концепции созданы как HTML/CSS-макеты по текстовым промптам, а не в GalileoAI или v0.dev. Промпты приведены в `ui_concepts/ui_description.md`, их можно использовать в этих сервисах.
- Открытые вопросы перед стартом разработки (см. раздел 9 ТЗ): PWA или нативное приложение, источник рецептов, офлайн-запись, юрисдикция.
