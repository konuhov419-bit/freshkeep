# UI-концепции FreshKeep

Главный экран «Инвентарь» в трёх вариантах. Концепции сгенерированы как HTML/CSS-макеты (аналог Text-to-UI: код получен по текстовому промпту с описанием стиля и компоновки). Исходный код и скриншоты лежат в этой же папке.

| # | Стиль | Компоновка | Код | Скриншот |
|---|---|---|---|---|
| 1 | Минимализм | Вертикальный список с группами | `concept_1_minimal.html` | `concept_1_minimal.png` |
| 2 | Яркий, дружелюбный | Сетка карточек 2×N + баннер с рецептом | `concept_2_bright.html` | `concept_2_bright.png` |
| 3 | Корпоративный | Дашборд: KPI-плитки + таблица | `concept_3_corporate.html` | `concept_3_corporate.png` |

## Промпты (использованы для генерации)

1. «Мобильный экран списка продуктов дома. Минималистичный стиль, белый фон, один акцент, группы "Скоро истекает" и "Свежее", цветные бейджи срока, плавающая кнопка +, нижняя навигация.»
2. «Мобильный экран инвентаря продуктов. Яркий дружелюбный стиль, градиенты, эмодзи-иконки, сетка карточек с прогресс-баром свежести, баннер с рецептом из продуктов с истекающим сроком.»
3. «Мобильный экран инвентаря в корпоративном стиле: синяя шапка, три KPI-плитки (просрочено / скоро / в норме), таблица продуктов со статусами, кнопки "Добавить" и "Сканировать".»

## Концепция 1 — Минимализм

**Особенности:** белый фон, один нейтральный акцент, типографика вместо иллюстраций; продукты сгруппированы по срочности; срок — цветной бейдж; FAB «+» для добавления.

**Преимущества**
- Высокая плотность: на экране видно 5–7 продуктов.
- Быстрое сканирование списка глазами.
- Простая реализация, хорошая доступность (высокий контраст).
- Легко масштабируется на длинные списки (50+ продуктов).

**Недостатки**
- Нейтральный вид, меньше эмоциональной вовлечённости.
- Рецепты и польза приложения на главном экране не видны.
- Нет иллюстраций — продукты труднее различить «с лёгкого взгляда».

## Концепция 2 — Яркая карточная

**Особенности:** градиентный баннер «приготовьте из того, что скоро испортится», сетка карточек с эмодзи и полосой свежести, фильтры-чипы по месту хранения, плавающая «пилюля»-навигация.

**Преимущества**
- Главная ценность (рецепт из продуктов с близким сроком) — на первом экране.
- Эмоциональный, дружелюбный, подходит студентам и молодым семьям.
- Прогресс-бар свежести считывается без чтения текста.
- Чипы мест хранения ускоряют навигацию.

**Недостатки**
- Ниже плотность: в сетке видно 4–6 карточек, длинный список прокручивается дольше.
- Больше визуального шума и затрат на дизайн иконок.
- Баннер занимает много места и может раздражать при повторных заходах.

## Концепция 3 — Корпоративная (дашборд)

**Особенности:** тёмно-синяя шапка, три KPI-плитки со счётчиками, таблица со статусами, две основные кнопки действий.

**Преимущества**
- Максимум информации: сразу видна «общая картина».
- Строгий понятный стиль, хорошо подходит для аналитики.

**Недостатки**
- Ощущение рабочего инструмента, а не домашнего помощника.
- Таблица плохо читается на узком экране смартфона.
- Не отражает основной сценарий (быстро открыть → увидеть → приготовить).

## Сравнение

| Критерий (вес) | К1 Минимализм | К2 Яркая | К3 Корпоративная |

## Выбор: Концепция 2 (яркая карточная)

**Обоснование**
1. **ЦА.** Основные пользователи — молодые семьи и студенты; им нужен тёплый, лёгкий интерфейс, а не «таблица».
2. **Ключевая ценность на первом экране.** Баннер с рецептом связывает учёт с действием («что приготовить»), что напрямую влияет на удержание (метрика D7).
3. **Мгновенная читаемость срока.** Цвет + полоса свежести + текст дублируют друг друга (не только цвет — важно для доступности).
4. **Масштабируемость решаема.** Недостаток плотности компенсируется режимом «Список» (переключатель вида) и поиском; в ТЗ это учтено как Should have.

**Что берём из других концепций**
- Из К1: компактный режим списка для длинных инвентарей.
- Из К3: счётчики «просрочено / скоро / в норме» в виде небольших чипов над сеткой.
