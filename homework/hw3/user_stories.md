## 2. User Journeys

### Journey 1. «Счастливый путь» — от покупки до ужина (Анна)
1. Возвращается из магазина → открывает приложение → нажимает «+».
2. Сканирует штрихкод молока → название и срок подставляются автоматически → подтверждает.
3. Повторяет для 5–6 продуктов (быстрый режим «добавить ещё»).
4. Через 3 дня приходит push «Йогурт и молоко скоро истекают».
5. Открывает баннер «Рецепт из продуктов» → выбирает «Омлет с сыром» → готовит.
6. Отмечает использованные продукты как «съедено» → количество уменьшается.

### Journey 2. Нормальный сценарий — ручной ввод без штрихкода (Макс)
1. Купил овощи на рынке (штрихкода нет) → «+» → «Ввести вручную».
2. Вводит название «Помидоры», количество 500 г, выбирает срок «+7 дней».
3. Продукт появляется в разделе «Холодильник».

### Journey 3. Совместное использование (Анна + муж)
1. Анна открывает «Профиль» → «Пригласить в семью» → отправляет ссылку.
2. Муж регистрируется по ссылке → видит общий инвентарь.
3. Муж отмечает, что продукт закончился → он автоматически попадает в список покупок Анны.

### Journey 4. Покупки с списком (Ольга)
1. Добавляет в список «Яйца» и «Йогурт».
2. В магазине отмечает «куплено» → приложение предлагает перенести в инвентарь и указать срок.

## 5. User Stories и критерии приёмки

Формат: «Как [роль], я хочу [действие], чтобы [результат]». Критерии: Given-When-Then; **[+]** — позитивный сценарий, **[−]** — негативный.

---

### US-01 (Must) Регистрация и вход
**Как** новый пользователь, **я хочу** зарегистрироваться по email и паролю, **чтобы** мои данные сохранялись и были доступны на другом устройстве.

- **[+]** Given я на экране регистрации и ввёл корректный email и пароль ≥ 8 символов, When нажимаю «Создать аккаунт», Then аккаунт создан, я попадаю на пустой главный экран с подсказкой «Добавьте первый продукт».
- **[−]** Given я ввёл email без символа «@», When нажимаю «Создать аккаунт», Then под полем показано «Введите корректный email», запрос на сервер не отправляется.
- **[−]** Given пароль короче 8 символов, When я нажимаю кнопку, Then показано «Пароль должен быть не короче 8 символов».
- **[−]** Given email уже зарегистрирован, When я пытаюсь зарегистрироваться, Then показано «Этот email уже используется. Войти?» со ссылкой на вход.
- **[−]** Given я ввёл неверный пароль при входе, When нажимаю «Войти», Then показано «Неверный email или пароль» (без уточнения, что именно неверно), поле пароля очищено.

---

### US-02 (Must) Добавление продукта вручную
**Как** пользователь, **я хочу** добавить продукт вручную с названием, количеством и сроком годности, **чтобы** учитывать продукты без штрихкода.

- **[+]** Given я на экране «Добавить продукт», When ввёл название «Молоко», количество «1 л», выбрал место «Холодильник» и срок «+7 дней» и нажал «Сохранить», Then продукт появляется на главном экране в карточке «Молоко» с оставшимся сроком «7 дней».
- **[+]** Given я сохранил продукт, When нажимаю «Добавить ещё», Then форма очищается, место хранения остаётся прежним.
- **[−]** Given поле «Название» пустое, When нажимаю «Сохранить», Then поле подсвечено красным с текстом «Укажите название», продукт не создан.
- **[−]** Given количество ≤ 0, When нажимаю «Сохранить», Then показано «Количество должно быть больше 0».
- **[−]** Given срок годности указан в прошлом, When нажимаю «Сохранить», Then показано предупреждение «Срок уже истёк. Добавить как просроченный?» с кнопками «Да» / «Изменить дату».

---

### US-03 (Must) Добавление продукта по штрихкоду
**Как** пользователь, **я хочу** отсканировать штрихкод камерой, **чтобы** название и категория подставились автоматически и ввод занял несколько секунд.

- **[+]** Given камера разрешена и штрихкод есть в базе, When навожу камеру на штрихкод, Then в течение 3 секунд открывается форма с заполненным названием; мне остаётся указать срок и количество.
- **[−]** Given штрихкода нет в базе, When сканирование завершено, Then показано «Продукт не найден. Введите данные вручную», штрихкод сохранён в форме.
- **[−]** Given доступ к камере запрещён, When нажимаю «Сканировать», Then показан экран «Нужен доступ к камере» с кнопкой «Открыть настройки» и ссылкой «Ввести вручную».
- **[−]** Given нет интернета, When сканирую штрихкод, Then показано «Нет соединения. Заполните данные вручную», штрихкод сохраняется в форму.

---

### US-04 (Should) Редактирование и удаление продукта
**Как** пользователь, **я хочу** изменить количество или удалить продукт, **чтобы** инвентарь отражал реальное содержимое холодильника.

- **[+]** Given я открыл карточку продукта, When меняю количество с 1 л на 0,5 л и сохраняю, Then карточка отображает 0,5 л.
- **[+]** Given я смахнул карточку влево, When подтверждаю «Удалить», Then продукт исчезает, внизу появляется «Отменить» на 5 секунд.
- **[+]** Given в течение 5 секунд я нажал «Отменить», When действие обработано, Then продукт возвращается на прежнее место.
- **[−]** Given я ввёл в количество текст «abc», When сохраняю, Then показано «Введите число».

---

### US-05 (Must) Индикация свежести
**Как** пользователь, **я хочу** видеть цвет и текст срока на карточке, **чтобы** сразу понимать, что нужно съесть первым.

- **[+]** Given до окончания срока > 3 дней, When открываю главный экран, Then полоса карточки зелёная, подпись «N дней».
- **[+]** Given до окончания срока 1–3 дня, When открываю главный экран, Then полоса оранжевая, подпись «N дня/дней», карточка в начале списка.
- **[+]** Given срок истекает сегодня или уже истёк, When открываю главный экран, Then полоса красная, подпись «сегодня» или «просрочено N дн.».
- **[−]** Given продукт без срока годности (необязательное поле), When открываю главный экран, Then карточка нейтрального серого цвета, подпись «без срока».

---

### US-06 (Must) Push-напоминания
**Как** пользователь, **я хочу** получать уведомление о скором окончании срока, **чтобы** успеть использовать продукт.

- **[+]** Given уведомления включены и у продукта срок истекает через 2 дня (настройка по умолчанию), When наступает 09:00 по моему времени, Then приходит одно push «Скоро истекает: Молоко, Йогурт».
- **[+]** Given несколько продуктов истекают в один день, When наступает время уведомления, Then они объединены в одно push.
- **[−]** Given я отключил уведомления в системе, When открываю приложение, Then на главном экране показан баннер «Включите уведомления, чтобы не пропустить сроки» с кнопкой «Включить».
- **[−]** Given я удалил продукт, When наступает время уведомления, Then о нём уведомление не приходит.

---

### US-07 (Should) Настройки уведомлений
**Как** пользователь, **я хочу** выбрать время и за сколько дней предупреждать, **чтобы** не получать лишних уведомлений.

- **[+]** Given я в «Профиль → Уведомления», When выбираю «За 3 дня» и время 19:00, Then настройки сохранены и новые напоминания приходят в это время.
- **[−]** Given нет соединения, When сохраняю настройки, Then показано «Не удалось сохранить. Повторить», выбранные значения остаются на экране.

---

### US-08 (Must) Рецепты из имеющихся продуктов
**Как** пользователь, **я хочу** увидеть рецепты из продуктов, которые у меня есть, **чтобы** быстро решить, что приготовить, и не выбросить продукты с близким сроком.

- **[+]** Given в инвентаре ≥ 3 продуктов, When открываю вкладку «Рецепты», Then вижу список рецептов, отсортированный по числу совпавших ингредиентов и близости срока.
- **[+]** Given на карточке рецепта указано «Есть 4 из 5 ингредиентов», When открываю его, Then видны недостающие ингредиенты и кнопка «Добавить недостающее в покупки».
- **[−]** Given в инвентаре < 3 продуктов, When открываю «Рецепты», Then показано «Добавьте больше продуктов, чтобы увидеть рецепты» с кнопкой «Добавить продукт».
- **[−]** Given подходящих рецептов нет, When открываю «Рецепты», Then показано «Ничего не нашли» и кнопка «Сбросить фильтры».
- **[−]** Given нет соединения, When открываю «Рецепты», Then показаны ранее загруженные рецепты с пометкой «Офлайн-режим»; если кэша нет, то «Нет соединения. Повторить».

---

### US-09 (Should) Фильтры рецептов
**Как** пользователь с диетой, **я хочу** фильтровать рецепты по времени и диете, **чтобы** получать подходящие варианты.

- **[+]** Given я в «Рецепты», When выбираю «до 20 мин» и «вегетарианское», Then в списке остаются только рецепты, удовлетворяющие обоим условиям.
- **[−]** Given фильтры дают 0 результатов, When применяю их, Then показан пустой экран с кнопкой «Сбросить фильтры».

---

### US-10 (Must) Список покупок
**Как** пользователь, **я хочу** вести список покупок, **чтобы** не забывать нужное и не покупать лишнее.

- **[+]** Given я на вкладке «Покупки», When ввожу «Яйца» и нажимаю «Добавить», Then позиция появляется вверху списка.
- **[+]** Given позиция в списке, When отмечаю «куплено», Then показано предложение «Добавить в инвентарь?» с формой срока.
- **[−]** Given название пустое, When нажимаю «Добавить», Then позиция не создаётся, поле подсвечено.
- **[−]** Given позиция «Яйца» уже есть в списке, When добавляю её снова, Then показано «Уже в списке» и количество не дублируется.

---

### US-11 (Should) Автодобавление закончившихся продуктов
**Как** пользователь, **я хочу**, чтобы закончившиеся продукты автоматически попадали в список покупок, **чтобы** не вносить их вручную.

- **[+]** Given у продукта количество уменьшено до 0, When я подтверждаю «Закончился», Then он добавлен в «Покупки» со ссылкой «Из инвентаря».
- **[−]** Given продукт с таким названием уже в списке, When количество становится 0, Then дубль не создаётся.

---

### US-12 (Should) Семейный доступ
**Как** глава семьи, **я хочу** пригласить близких в общий инвентарь, **чтобы** все видели актуальное состояние холодильника.

- **[+]** Given я в «Профиль → Семья», When отправляю приглашение и получатель принимает его, Then он видит тот же инвентарь и список покупок.
- **[+]** Given другой участник добавил продукт, When я обновляю экран, Then вижу новый продукт в течение 5 секунд.
- **[−]** Given ссылка-приглашение старше 7 дней, When по ней переходят, Then показано «Приглашение устарело. Попросите новое».
- **[−]** Given я не владелец семьи, When пытаюсь удалить участника, Then кнопка недоступна, а API возвращает 403.

---

### US-13 (Should) Режим списка и поиск
**Как** пользователь с большим инвентарём, **я хочу** переключиться на компактный список и искать по названию, **чтобы** быстро найти нужный продукт.

- **[+]** Given в инвентаре 50 продуктов, When ввожу «мол», Then показаны только продукты, чьё название содержит «мол», в течение 300 мс.
- **[−]** Given нет совпадений, When ввожу «xyz», Then показано «Ничего не найдено по запросу “xyz”».

---

### US-14 (Nice) Шаблоны популярных продуктов
**Как** пользователь, **я хочу** выбрать продукт из шаблонов (молоко, яйца, хлеб), **чтобы** срок подставлялся автоматически.

- **[+]** Given я в форме добавления, When начинаю вводить «мол», Then вижу подсказку «Молоко (обычно 7 дней)»; при выборе срок заполняется.
- **[−]** Given подсказок нет, When ввожу уникальное название, Then форма работает как обычный ручной ввод.

### US-15 (Nice) Вход через Google
**Как** пользователь, **я хочу** войти через Google, **чтобы** не запоминать пароль.

- **[+]** Given я нажал «Войти через Google» и подтвердил доступ, When возвращаюсь в приложение, Then я авторизован.
- **[−]** Given я отменил вход в окне Google, When возвращаюсь, Then показано «Вход отменён», экран входа не сброшен.

### US-16 (Nice) Избранные рецепты
**Как** пользователь, **я хочу** сохранять рецепты в избранное, **чтобы** быстро находить любимые.

- **[+]** Given я открыл рецепт, When нажимаю «сердечко», Then рецепт появляется в разделе «Избранное».
- **[−]** Given нет сети, When нажимаю «сердечко», Then действие ставится в очередь и синхронизируется при появлении сети.

### US-17 (Nice) Статистика food waste
**Как** осознанный потребитель, **я хочу** видеть, сколько продуктов я выбросил и съел вовремя, **чтобы** отслеживать прогресс.

- **[+]** Given я отметил 10 продуктов «съедено» и 2 «выброшено» за месяц, When открываю «Статистика», Then вижу долю 83% съеденного вовремя.
- **[−]** Given данных меньше чем за неделю, When открываю «Статистика», Then показано «Недостаточно данных. Пользуйтесь приложением ещё N дней».

## 6. Обработка ошибок (Edge Cases)

### 6.1 Счастливые пути ключевых функций

| Функция | Счастливый путь |
|---|---|
| Инвентарь | «+» → скан штрихкода → подтверждение срока → карточка на главном экране (≤ 15 сек) |
| Напоминания | Продукт истекает через 2 дня → push в 09:00 → открытие → карточка продукта |
| Рецепты | Баннер на главной → рецепт с совпадением ингредиентов → «Готовлю» → продукты списаны |
| Список покупок | Добавил позицию → «куплено» → перенос в инвентарь |
| Аккаунт | Регистрация → пустой экран с подсказкой → добавление первого продукта |

### 6.2 Список возможных ошибок (сгенерирован с помощью AI и отобран)

**Ошибки валидации:** пустые обязательные поля; некорректный email; слабый пароль; отрицательное/нулевое количество; нечисловое количество; дата в прошлом; слишком длинное название (> 100 символов); дубликат позиции; эмодзи и спецсимволы в названии (допустимы, но экранируются).

**Отсутствие данных:** пустой инвентарь; пустой список покупок; нет рецептов; пустые результаты поиска и фильтров; штрихкод не найден; нет статистики.

**Сетевые ошибки:** нет интернета; таймаут (> 10 сек); ответ 5xx; обрыв при синхронизации; конфликт одновременного редактирования двумя участниками семьи.

**Неавторизованный доступ:** истёкшая сессия (401); доступ к чужому инвентарю (403); приглашение недействительно; удалённый аккаунт; токен отозван.

**Системные/разрешения:** нет доступа к камере; запрещены уведомления; нет места на устройстве.

### 6.3 UX-решения

| Тип | Ситуация | Решение (что видит пользователь) |
|---|---|---|
| **Валидация** | Пустое поле / неверный формат | Красная рамка + текст под полем (inline), фокус на первое ошибочное поле; кнопка «Сохранить» остаётся активной; сообщения конкретные («Укажите название»), без технических кодов |
| **Валидация** | Дата в прошлом | Мягкое предупреждение с выбором «Добавить как просроченный» / «Изменить дату» |

| **Нет данных** | Пустой поиск/фильтр | Текст «Ничего не найдено», кнопка «Сбросить» |
